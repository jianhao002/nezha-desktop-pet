# 小游戏使用与扩展

## 试玩

0.7.0 内置十三款游戏，从宠物右键或托盘的“小游戏”打开独立小窗。游戏与养成面板可以同时打开，成绩和本局单独保存，不改变哪吒的金币、经验、体力或现有动作。游戏列表可以上下滚动。

| 游戏 | 操作与模式 |
| --- | --- |
| 扫雷 | 左键点开、右键插旗、双击数字展开；首点及周围八格安全；入门到专家五档；各档记录最快通关时间 |
| 贪吃蛇 | 方向键 / WASD，空格开始或暂停；经典 / 穿墙，悠闲到极限七档速度；按模式与速度分别记录最高分 |
| 2048 | 方向键 / WASD，或下方箭头按钮；记录最高分；合出 2048 后可以继续 |
| 俄罗斯方块 | 四档初始速度；← → 移动、↑ 旋转、↓ 加速、空格直落、P 开始 / 暂停；下一块与落点影子；记录结束时最高分 |
| 打砖块 | 轻松 / 标准 / 挑战，鼠标或 ← → 控制挡板、空格发球 / 暂停；三次机会；结束时记录最高分 |
| 记忆翻牌 | 6 / 8 / 12 对；点击卡片配对，未配对的两张稍后收回；完成后记录最少翻牌次数 |
| 数独 | 入门 / 简单 / 标准 / 挑战，题目均检查唯一解；点格子再点数字，或键盘 1～9 / Delete；提示辅助练习，未使用提示完成时记录最短用时 |
| 五子棋 | 9×9 / 13×13 / 15×15，轻松 / 标准 / 认真三档电脑；你执黑先行，无禁手，横竖斜五子及以上获胜；按棋盘与对手分别记录最少获胜手数 |
| 数字华容道 | 3×3 / 4×4 / 5×5；点空格旁的数字，方向键 / WASD 移动空格；题目从合法移动生成；完成后记录最少步数 |
| 莲宝连连看 | 6×6 / 8×6 / 10×8，点两枚相同图案，连线最多转两次弯，可绕棋盘外侧；提示、每局三次洗牌；不倒计时，未使用辅助完成时记录最少尝试次数 |
| 莲火消消乐 | 三色 / 四色 / 五色，点击至少两块相邻同色方块成片消除；方块下落并收拢空列，大面积得分更高，全部清空加 1000 分；可撤销最近 20 步 |
| 纸牌接龙 | 翻一张 / 翻三张，点牌或牌组再点目标列；红黑交替降序排列，空列只接 K；同花色从 A 向上收牌；撤销最近 20 步和提示，建议普通窗口模式 |
| 哪吒点莲灯 | 5×5 / 7×7 / 9×9，左键顺时针旋转线路，接通中心莲火与全部灯；右键锁定 / 解锁格子；不倒计时，记录最少旋转次数 |

难度、棋盘、模式和速度的下拉选择在点击“新一局”后生效。“新一局”重新开始，替代该游戏原来的本局。返回列表、关闭小窗或正常退出桌宠都会保存尚未结束的一局，再次打开同一游戏自动继续。每款游戏各保留一局，不需要同时打开十三个窗口。

### 退出后继续上一局

- 十三款内置游戏均保存棋盘、分数 / 步数、当前难度和必要的内部状态；纸牌与消消乐同时保存撤销历史。扫雷 / 数独只累计实际游戏时间，退出期间不计时。
- 贪吃蛇、俄罗斯方块、打砖块恢复后先暂停，点击“开始 / 继续”或对应键再玩。记忆翻牌保留已经翻开的牌，未配对牌在恢复后重新给足观察时间。
- 每五秒自动保存一次；切走暂停、收起、返回列表、关闭窗口和正常退出时也保存。强制结束进程或断电时，最后几秒可能尚未保存；不能保证未完成的写入一定恢复。
- 已结束的一局不自动重开，下一次打开会开始新棋盘。保存的结束标记防止旧备份把已结束的一局复活。
- 存档损坏时优先读取可解析的备份；若本局的版本或数值校验失败，显示提示并保留旧文件，点击“新一局”才替换。正常关闭时若写入失败，保留当前窗口，恢复目录写入后再退出。
- 旧 0.6.1 没有本局存档，因此升级前正在玩的棋盘无法补存；从 0.7.0 开始的新局才有此能力。原最佳成绩、养成存档和自定义游戏继续保留。

扫雷档位：入门 6×6 / 4 雷、简单 9×9 / 10 雷、普通 12×12 / 24 雷、困难 14×14 / 40 雷、专家 16×16 / 64 雷。默认仍是简单；困难与专家可以用普通窗口模式或手动放大小窗。原有 9×9 和 12×12 通关记录继续使用。

贪吃蛇速度：悠闲 320 ms、轻松 260 ms、慢速 220 ms、标准 150 ms、快速 95 ms、困难 70 ms、极限 50 ms（每步间隔）。默认仍是标准。0.5.0 的模式总成绩保留并显示为“旧版”，不直接当作某一速度的纪录；新成绩按模式与速度分开保存。选择其他档位不会改变当前一局的计时或成绩归属。

俄罗斯方块四档初始下落间隔为 900 / 650 / 420 / 250 ms，默认标准；每消十行提升一级并加快，最快间隔 100 ms。使用七种方块的随机袋，支持靠墙旋转与直落。

打砖块三档为 3 / 4 / 5 行砖墙、190 / 240 / 290 的球速，默认轻松。丢球扣一次机会后等待重新发球，不会连续扣机会。

记忆翻牌默认 6 对，所有汉字都恰好出现两次。未配对卡片 750 ms 后收回，切走或收起会冻结这个延时；恢复后重新给足观察时间。

数独四档目标提示数为 46 / 40 / 34 / 30，默认简单。生成过程中保留唯一解，若不能再删除提示则保留实际题目。重复数字标红；固定提示不可改。计时从第一次填写开始，切走会停止；使用提示的本局仅作练习，不计最佳用时。数独、方块与较大五子棋棋盘建议使用普通模式或放大小窗。

普通、低调、极简三种模式调整窗口大小和默认透明度；也可以拖动右下角改变尺寸，再用滑块调整透明度。低调与极简不显示任务栏按钮。置顶默认关闭，可自行开启。“切走暂停”默认开启；勾选时切到其他窗口会暂停，切回来继续。贪吃蛇原先手动暂停的状态仍保留。

- 小窗内按 `Esc` 或点“收起”：隐藏并暂停。
- `Ctrl+Alt+H`：全局收起 / 恢复已有小游戏窗口。
- 如果快捷键已被其他软件占用，底部显示从宠物右键或托盘恢复的提示。这两处“小游戏”入口一直可以恢复。

这些设置调节屏幕上的显示方式，不隐藏程序进程，也不拦截系统截图。

## 放一个文件夹就能接入

在游戏列表点“添加游戏”，会打开**运行目录**的 `games`。把仓库中的 [examples/my-game](../examples/my-game) 整个文件夹复制进去，再点“刷新列表”，即可打开示例，无需重新编译桌宠或安装额外运行环境。

```text
运行目录/
  NezhaPet.exe
  games/
    my-game/
      game.json
      Game.cs
  data/
    mini-games/
      window.json
      bundled-index.json
      scores/my-game/records.json
      scores/my-game/session.json
```

新游戏用自己的文件夹和 `id`，例如 `reversi`。文件夹名与 `id` 一致，使用小写字母、数字、短横线，最长 48 字符。不要沿用其他游戏的 ID。

清单示例：

```json
{
  "apiVersion": 1,
  "id": "my-game",
  "name": "小游戏接入示例",
  "description": "演示界面、暂停、本地成绩和宠物信息。",
  "author": "你的名字",
  "entryType": "NezhaExample.TapGame",
  "sources": ["Game.cs"]
}
```

`entryType` 对应公开、非抽象、带无参数构造函数的 C# 类；`sources` 列出本文件夹内 1～8 个 `.cs` 文件，不接受子目录、上级路径或链接。清单不超过 64 KB，每个源码不超过 512 KB。图片等附加资源可放在游戏目录，通过 `Host.GameDirectory` 定位。

首次打开时使用系统 .NET Framework C# 编译器编译本地源码，界面采用 WPF。按现有示例使用兼容 Framework 编译器的 C# 语法；当前接口不加载 NuGet 包或第三方 DLL。编译失败会显示错误，可以返回列表打开其他游戏。改过代码后返回列表并重新打开，加载新代码。

游戏源码在桌宠进程中执行，拥有普通本地程序的权限；这是可信本地扩展接口，不是安全沙箱。只放入自己编写或确认可信的游戏。

## 游戏接口

继承 `NezhaDesktop.MiniGames.MiniGameControl` 可以减少接入代码：

| 成员 | 用途 |
| --- | --- |
| `Build()` | 在 UI 线程构建界面，此时 `Host` 已就绪 |
| `SetHostPaused(bool)` | 响应收起、焦点变化；停止计时与输入，保留棋盘及原有手动暂停状态 |
| `Dispose()` | 离开游戏 / 关闭窗口时释放计时器和外部事件订阅 |
| `Host.Pet` | 当前宠物只读快照：名字、等级、体力、心情；独立测试时可能为空 |
| `Host.Notify(text)` | 在小窗底部显示简短反馈 |
| `Host.Best(key, fallback)` | 读取本游戏的最佳成绩 |
| `Host.Record(key, value, lowerIsBetter)` | 仅保存更好的成绩；返回是否改善；保存失败会抛出异常 |
| `Host.GameDirectory` | 本游戏资源目录 |
| `CanResume` | 可选能力，默认 false；内置游戏 override 为 true，原自定义游戏无需改接口 |
| `CaptureSession()` / `RestoreSession(string)` | 可选实现：返回只包含规则状态的普通对象，或校验并恢复 JSON；已结束时返回 null |
| `NewSession()` | 新一局时调用，允许替换之前读取失败的本局存档 |

成绩键使用 1～48 个小写字母、数字、短横线，数值为非负整数。记录按游戏 ID 隔离，使用临时文件、原子替换和 `.bak` 备份。游戏要显示保存失败提示，并保持本局可玩。

本局也按游戏 ID 隔离，保存到 `scores/<id>/session.json`，与 `records.json` 的最佳成绩分开。IMiniGame 的旧 v1 方法保持兼容；续局通过可选 IMiniGameSession 能力调用。恢复时先校验数组长度、范围和规则约束，再替换当前棋盘；不要保存窗口、计时器或宠物可变引用。每份本局最大 256 KB，不能借此操作养成存档。

计时类游戏在暂停时停止计时器；恢复时不要把暂停期间算进游戏时间。关闭窗口不能留下继续运行的计时器。长计算应避免占住 UI 线程，UI 和成绩调用保持在 UI 线程。

宠物快照为未来“哪吒陪玩”留下入口。当前接口不直接改养成存档、不发金币或经验、不触发动作。后续需要奖励或动作时，再通过规则层设计操作检查、保存和重复结算保护，与公司电脑的动作实现一起评审。

## 内置游戏与更新兼容

仓库 `games/<id>` 保存正式内置游戏的清单与源码；构建脚本自动将这些文件嵌入 `NezhaPet.exe`，不需要在主程序写游戏注册表。`examples` 仅是扩展示例，不放入默认列表。

首次打开列表时把内置文件释放到运行目录。升级时，未改过的内置文件可以更新；检测到本机编辑过的内置游戏则保留整个文件夹并提示。自行添加的文件夹也保留。为减少更新冲突，自己的游戏使用新 ID。

0.4.1 更新器只接受原有程序 / 配置 / README / 素材结构，因此发布 ZIP 中不添加 `games` 或示例目录。嵌入后仍使用原有 ZIP 白名单和更新链路。小游戏本地设置与成绩在 `data/mini-games`，发布包不携带；复制整个运行目录换电脑时可一起带走。

## 验证

在源码目录运行 `build.ps1` 后运行 `scripts/Test.ps1`，会一并验证原有功能、十三款游戏规则、真实 WPF 窗口、收起暂停和实际扩展示例。本局检查包含所有游戏的读写恢复、异常存档保护、保存失败不丢棋盘，以及两个独立进程之间的真实退出 / 再启动。所有测试使用新的 `qa` 子目录。

只验证小游戏与示例：

```powershell
Set-Location -LiteralPath 'F:\nezha-desktop-pet\source'
.\dist\nezha-desktop-v0.7.0\NezhaPet.exe --minigame-test 'F:\nezha-desktop-pet\source\qa\my-new-test' 'F:\nezha-desktop-pet\source\examples\my-game'
```

报告目录必须尚不存在。省略最后一个示例路径也可以只验证内置游戏与临时扩展。多显示器、其他电脑的显示缩放和全局快捷键占用仍需目标电脑实机试玩。

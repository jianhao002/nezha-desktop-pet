## 开发目录与运行目录

开发目录像厨房，存放源码、素材和打包脚本。运行目录像送到用户手里的成品，只有 exe、素材、配置和用户自己的 `data` 存档。日常双击运行发布包里的 `NezhaPet.exe`，不要直接在源码目录保存游戏进度。

| 目录/文件 | 用途 | 上传到 Git |
| --- | --- | --- |
| `src`、`updater` | 桌宠、更新助手源码 | 是 |
| `assets`、`config.json` | 动作素材、养成规则 | 是 |
| `update-settings.json` | 公开更新源地址，没有凭证 | 是 |
| `scripts`、`docs` | 本机测试、打包、发布和说明 | 是 |
| `games`、`examples` | 内置小游戏源码、独立扩展示例 | 是 |
| `dist` | 编译生成的程序与发布压缩包 | 否，发布到 GitHub Releases |
| `qa` | 本机测试报告与预览 | 否 |
| 运行目录的 `data`、`.update` | 游戏存档、更新暂存及旧版备份 | 否 |

## 一键更新

在桌宠右键菜单或托盘菜单选择更新功能，检查新版后下载并安装。下载期间可以看到状态；更新前会保存当前进度，安装时桌宠会退出，再自动启动。

更新链路：读取 GitHub 最新正式发布中的 `update.json` → 比较版本 → 下载指定版本发布包 → 校验大小和 SHA256 → 检查压缩包路径与文件白名单 → 保存存档 → 暂存目录中的更新助手等待旧程序退出 → 备份并替换程序 → 启动检查 → 重启桌宠。

SHA256 相当于包的“指纹”，用于检查下载包是否与发布者的清单一致。发布包只有程序、素材和配置；`data` 不参与替换。更新失败时助手会尝试恢复旧程序；`.update` 里保留状态与旧文件，排查前不要手动删除。

上传源码和发布桌宠是两个步骤。`git push` 只上传源码；维护者还需要运行发布脚本，生成并上传正式压缩包和更新清单，其他电脑的更新按钮才会发现新版。公开下载不需要登录 GitHub；只有维护者上传源码和发布时需要自己的凭证。

### 从旧极狐版迁移

退出桌宠并备份原程序目录。从 GitHub 发布页下载完整 ZIP，解压后将程序、配置和素材复制到原运行目录，保留原来的 `data`、`games`、`.update`。不要只改旧程序的更新设置：旧版本还不认识 GitHub 下载地址。安装完成后双击新版 `NezhaPet.exe`，以后可以正常使用更新按钮。

## 启动和操作

1. 把完整压缩包解压到可写目录，例如“文档”。请先解压，不要直接在压缩包里双击。
2. 双击 `NezhaPet.exe`。
3. 左键拖动哪吒；轻点头部、身体、左右手、风火轮、神环触发不同反馈。
4. 右键哪吒 → 养成面板，进入背包、打工、零食铺。
5. 在“小屋”调整大小，或开启偶尔桌面游走。默认关闭游走。
6. 关闭养成面板不会退出桌宠；从右键菜单或右下角托盘选择“退出”。隐藏后可从托盘恢复。
7. 在“成长”查看本级经验、下一级解锁内容和成长礼。
8. 在“小屋”的“午睡补元气”卡片让哪吒睡一会儿；也可从右键或托盘菜单睡觉、叫醒。
9. 右键哪吒或托盘 → 小游戏，打开扫雷、贪吃蛇或 2048。`Esc` 收起，`Ctrl+Alt+H` 收起 / 恢复；快捷键占用时可从原入口恢复。

初始提供 50 金币、2 份桂花糖。金币是本地游戏数值，不涉及真实支付。

### 休闲小游戏

小窗提供普通、低调、极简三种尺寸和透明度预设，透明度可单独调整，默认切走暂停。收起保留本局，返回列表或退出程序结束本局。扫雷用鼠标，贪吃蛇用方向键 / WASD、空格暂停，2048 用方向键 / WASD 或箭头按钮。成绩单独保存在 `data/mini-games`，不影响养成进度。

游戏列表点“添加游戏”，把新游戏文件夹放入打开的 `games` 目录，再刷新列表即可。接入示例、接口和更新兼容设计见 [小游戏使用与扩展](docs/MINI_GAMES.md)。

### 养成流程

打工消耗体力、饱腹 → 等待完成 → 领取金币 → 零食铺买点心 → 背包喂食；体力不足时可以午睡，叫醒后恢复体力。

- 一次只能接一份工作；完成后手动领取，重复领取不会重复发钱。
- 打工中不能喂食，先领取报酬。
- 关闭程序仍会按截止时间计算打工完成。调整系统时间会影响这个离线倒计时。
- 非打工、非午睡时每小时恢复 20 体力；每小时饱腹减少 6、非午睡时心情减少 2。
- 重新打开时，离线属性变化最多按一小时计算。
- 摸摸哪吒增加心情，同一轮 8 秒内连续点击只增加一次；午睡中先叫醒，点击不会增加互动经验。
- 数值达到 100 不会继续增加，饱腹已满时不会消耗零食。
- 桂花糖、莲蓉包、仙桃各有独立的 Q 版吃东西动画：轻轻尝糖、双手捧包子鼓脸颊、咬仙桃后开心脸红。
- 吃东西动画完整播放一遍，最后的满足表情短暂停留，然后恢复待机。首次渲染或短暂卡顿会稍微减慢动作，而不会跳掉中间的姿势。
- 吃东西或有限互动动作播放时，新点击、喂食、出发打工和睡觉会提示稍等，等待动作结束再操作；不会先扣物品再丢掉动作。购物可继续，提示不会切走正在播放的动画。

### 午睡与叫醒

一次完整午睡 180 秒，叫醒后最多恢复 25 体力、4 心情，属性不会超过 100。随时可“提前叫醒”，恢复量按已睡时间比例计算。睡满后会继续等你“叫醒哪吒”才结算，超过时长不增加额外奖励，重复叫醒也不会重复恢复。

睡觉期间暂停体力自然恢复与心情衰减，饱腹继续减少。打工与休息不能同时进行；午睡中先叫醒再喂食或接工作。关闭后再打开，睡眠状态和开始时确定的奖励仍保留，叫醒时按时间结算。本机时钟变化会影响这个离线计时。

## 等级怎么升级，有什么用

经验像累计积分，等级像会员档位。经验一直保留，达到累计门槛后进入下一等级。

| 等级 | 累计经验 | 称号与实际收益 |
| --- | ---: | --- |
| Lv.1 | 0 | 小小哪吒：桂花糖、陈塘关巡城 |
| Lv.2 | 20 | 元气伙伴：莲蓉包及其专属吃法、天宫送信；成长礼 10 金币 |
| Lv.3 | 60 | 红绫小将：仙桃及其专属吃法、守护香火；成长礼 15 金币 |
| Lv.4 | 120 | 风火守护：新接工作报酬增加 5%；成长礼 20 金币 |
| Lv.5 | 220 | 莲火神将：新接工作报酬增加 10%；成长礼 30 金币 |

经验来源：

- 喂桂花糖 +4、莲蓉包 +6、仙桃 +8；每日喂食经验最多 36。达到经验上限后仍可正常喂食、增长属性。
- 部位互动每 8 秒最多 +1；每日互动经验最多 10。
- 完成并领取打工报酬获得 +6 / +18 / +30，按接任务时保存的工作快照结算。
- 购物本身不增加经验。每日上限使用本机日期；这不是联网防作弊系统。

工作收益加成按接任务时等级固定，四舍五入到整数金币。打工期间升级不会追溯修改已接工作的报酬。成长礼每级只发一次，跨多个等级时会补齐。

这些是试玩阶段的初始数值，可以根据体验调整。达到 Lv.5 后仍可累计经验，后续在配置里追加等级。

## 换电脑与存档

退出桌宠后复制整个程序文件夹，包括 `assets`、`config.json` 和 `data`。在另一台 Windows 电脑完整解压后，双击 exe 即可继续。

`data/save.json` 保存金币、背包、打工与午睡记录、属性、大小与位置，`data/save.json.bak` 是上一次有效存档备份。首次启动时自动生成 `data`。存档有备份恢复能力，但恢复后最后一次操作可能回退；两个文件都损坏时会报错，不会悄悄重置。

### 历史：0.3.1 更新到 0.4.1

在更新菜单检查已经发布的新版，安装前会保存当前进度。0.4.1 含午睡记录，存档格式为 3；格式 1 / 2 自动迁移，保留金币、背包、累计经验和已接工作。升级后的存档不能交给 0.3.1 及更早程序使用，回退时使用保留的旧版目录和它原来的存档。

### 0.1 / 0.2 第一次手工升级

1. 退出旧版桌宠。
2. 将当前完整发布包解压到一个新目录，确认同时包含 `NezhaPet.exe`、`NezhaUpdater.exe`、`assets`、`config.json` 和 `update-settings.json`。
3. 在首次启动前，把旧版整个 `data` 文件夹复制到新版程序目录。
4. 双击新版 exe。格式 1 / 2 存档会自动升级到格式 3，保留金币、背包、累计经验和进行中的工作，并补发尚未领取的成长礼。
5. 以后在更新菜单安装已经发布的新版。0.1 / 0.2 程序没有更新功能，第一次升级需要按上述方式复制。

历史上的 0.3.1～0.4.1 使用极狐 GitLab 数字项目 ID 检查更新。迁移到 GitHub 时仍需手动安装完整新版，保留原 `data`；不能通过旧极狐更新通道直接切换仓库。

旧版已经买到的高等级零食仍然可以喂食；等级限制用于新购买和新接工作。

程序使用 Windows .NET Framework 4.x 和 WPF，面向 Windows 10 / 11。当前电脑已编译并验证；其他电脑、多显示器与不同缩放比例尚需实际运行验收。无需 Python、Node.js 或数据库。没有自动开机启动。

## 当前动作与后续方向

动作包含原来的 9 类基础动画、3 套 Q 版吃东西动画，以及摸头、身体挠痒和睡觉动作，共 15 类。左右手继续使用红绫回应。点击神环会有大尺寸半透明呼吸光与星光，点击风火轮会有红金拖尾与火星；这些特效由程序绘制，不需要新增成套图片。

下一阶段建议先做几个每日小目标和完成反馈，再增加可购买的饰品外观。新等级优先解锁动作、外观和玩法。详细顺序与验收边界见 [后续功能路线](https://github.com/jianhao002/nezha-desktop-pet/blob/main/docs/ROADMAP.md)。

## 增加动作、零食和工作

先退出程序；用 UTF-8 编辑 `config.json`，再启动。动作名在 `animations` 中注册，各互动/零食/工作通过 `animation` 引用它。

### 方式一：逐帧透明 PNG

例如把 6 张吃东西的图放到 `assets/eat/00.png` ～ `05.png`，在 `animations` 中新增：

```json
"eat": {
  "files": ["assets/eat/00.png", "assets/eat/01.png", "assets/eat/02.png", "assets/eat/03.png", "assets/eat/04.png", "assets/eat/05.png"],
  "frameMs": 140,
  "loop": false,
  "durationMs": 1150
}
```

再把 `foods` 中对应零食的 `animation` 改为 `eat`。建议所有帧使用相同透明画布尺寸，人物位置保持一致。`frameMs` 是每帧播放的毫秒数。互动默认播放 2.8 秒，长动作至少完整播放一轮；`durationMs` 指定持续时间，`loop: false` 表示不循环，末帧会停留到动作结束。

### 方式二：横排或多行图集

```json
"touchHead": {
  "sheet": "assets/touch-head.png",
  "row": 0,
  "frames": [0, 1, 2, 3, 4, 5],
  "columns": 2,
  "frameWidth": 512,
  "frameHeight": 512,
  "frameMs": 220,
  "durationMs": 1650,
  "loop": false
}
```

`row` 和 `frames` 都从 0 开始。这个例子使用 1024 × 1536 的图集：`columns: 2` 表示每行两帧，编号 0、1 在第一行，2、3 在第二行，4、5 在第三行。省略 `columns` 或设为 0 时，所有帧仍从 `row` 指定的横排读取。每个动作允许自己的帧尺寸；省略时使用顶层 `frameWidth`、`frameHeight`。

### 身体点击区域

`interactions` 的 `x/y/width/height` 使用 0～1 的比例坐标，覆盖单张动作画布。缩放桌宠后仍按比例命中。配置数组从前往后匹配，重叠时优先使用前面的区域。

点击链路：鼠标坐标 → 检查当前帧像素是否可见 → 匹配身体区域 → 检查动作占用 → 执行互动规则并保存 → 播放 `animation`。

移动超过阈值按拖动处理，不会在拖动结束时触发部位互动。

### 扩展养成内容

- 添加零食：在 `foods` 加一个唯一 `id`、价格、属性增量、反馈动作。
- 添加打工：在 `jobs` 加一个唯一 `id`、时长、消耗、报酬、反馈动作。
- 食物与工作用 `minimumLevel` 指定解锁等级；食物的 `experience` 指定喂食经验。
- `growth.levels` 定义等级门槛、称号、一次性成长礼和工作收益加成，等级须从 1 开始连续、经验递增。`benefit` 是面板显示文字；实际解锁由物品和工作的 `minimumLevel` 决定。
- 保持原有物品 `id` 不变，才能保留背包中的数量。
- 进行中的工作保存启动时的报酬快照，后续修改配置不会改变已接工作的报酬。
- `rest` 设置午睡时长、体力/心情恢复与睡觉动作；已开始的午睡保存自己的奖励快照，不随以后配置改动变化。
- 更复杂的任务、装备、房间、连续动作等需要增加规则代码，初版没有这些功能。

## 源码结构与编译

源码仓库包含 `src`、`updater`、`build.ps1`、`scripts`、`app.manifest`。运行发布包不含源码。

- `Core.cs`：配置、金币/物品/打工/午睡规则、原子存档和回滚。
- `Desktop.cs`：透明桌宠窗口、动画播放器、点击区域、托盘、养成面板。
- `AnimationPlayer.cs`：动作占用与完整播放、神环呼吸光、风火轮拖尾。
- `Program.cs`：启动、同目录单实例限制、UI 预览。
- `Tests.cs`：经济流程、午睡结算、重启、重复领奖、存档失败等验证。
- `UpdateCore.cs`：公开更新源、版本检查、下载、压缩包校验与暂存计划。
- `updater/Program.cs`：等待旧程序退出，备份、替换、检查启动、失败恢复。
- `MiniGameApi.cs`、`MiniGameCatalog.cs`、`MiniGameWindow.cs`：小游戏接口、文件夹发现 / 编译与可调小窗。
- `games/<id>`：三款内置小游戏，构建时嵌入 exe；`examples/my-game`：无需重编译主程序的接入模板。

在 Windows PowerShell 中进入源码目录后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Package.ps1
```

编译使用 Windows 自带 Framework C# 编译器，无需下载依赖。输出放到 `dist/nezha-desktop-v版本号`；测试报告写入新的 `qa/run-*` 目录，不读取真实游戏存档。`Package.ps1` 默认重新编译并运行测试，再生成扁平结构的发布压缩包和更新清单。发布凭证不在源码、配置或压缩包中。

本地游戏存档可被用户编辑；当前是个人离线玩具，没有联网排行榜、账号同步或防作弊系统。素材通过内置 ImageGen 生成，提示词见源码中的 `ART_PROMPTS.md` 与 `ART_PROMPTS-v0.4.0.md`。仓库已有成品透明帧和图集，编译时不需要图片生成工具或 Python。

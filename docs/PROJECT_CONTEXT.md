核对日期：2026-10-01。核对来源：源码、提交历史、公开更新清单、本机运行包及其更新状态。

这份文件是两台开发电脑共享的项目记录。它保存必要背景和决定，不声称恢复了公司电脑上未同步的聊天、未提交代码或个人记忆。

## 项目是什么

“焰轮哪吒”是个人制作的 Windows 离线桌面宠物，以哪吒、中国神话、红绫、神环和风火轮为视觉与玩法元素。成品使用 C#、WPF 和 Windows .NET Framework，面向 Windows 10 / 11。

日常养成离线运行，无需 Codex、GPT 账号、Git、Python、Node.js 或数据库。检查和下载更新需要联网。

当前已有：透明桌宠与拖动、像素穿透、部位互动、托盘和养成面板、桌面游走开关、三种零食及专属吃法、打工赚金币、等级与解锁、一次性成长礼、午睡与叫醒，以及保留存档的一键更新。配置注册 15 类动作。

## 已确认的决定

### 用户在本轮确认

- 公司电脑与家庭电脑接续开发，采用把项目背景、关键决定和交接状态放进 Git 的方式。
- 用根目录 `AGENTS.md` 引导 Codex 阅读本文件；开发记录随源码同步，减少每次换电脑重复解释背景。
- 开发路径不放在 C 盘。家庭电脑统一使用父目录 `F:\nezha-desktop-pet`：源码固定为 `source`，日常试玩固定为 `preview`，旧试玩备份放 `archive`。后续小改动复用这些目录。原安装目录 `F:\nezha-desktop-pet-0.3.1` 保持独立。其他电脑选择自己的非系统盘源码目录。

### 已有实现与文档确立的设计

- 保持个人离线养成结构，当前没有账号同步、联网排行榜、真实支付或服务器依赖。
- `data/save.json` 和 `.bak` 属于每台电脑自己的游戏进度；Git 和发布包不携带这些数据。代码同步不会自动合并两台电脑的游戏存档。
- 更新下载已编译的正式发布包。上传源码和发布桌宠是两个步骤；仅 `git push` 不会让更新按钮发现新版。
- 使用公开包下载，使用者无需配置 GitLab 令牌。维护者的发布凭证使用现有隐藏输入流程。
- 界面与养成账目分层：规则检查 → 结算 → 保存 → 动作反馈。保存失败时回退本次内存变化。
- 保留现有食物和工作 ID。正在进行的工作、午睡保存开始时的奖励快照，后续调整配置不追溯改变已开始的活动。
- 吃东西和有限互动完整播放后再释放动作占用；新操作在扣物品、发奖励之前检查占用状态。
- Lv.1～Lv.5、每日喂食/互动经验上限沿用现有配置。新增等级应有对应动作、外观或玩法内容。

不要把下面的路线建议视为用户已批准立即开发的任务。

更新流程：读取 `latest/update.json` → 比较版本 → 下载固定版本 ZIP → 校验大小和 SHA256 → 检查 ZIP 路径、文件白名单及配置/素材 → 保存当前进度 → 暂存助手等待原进程正常退出 → 备份并替换程序 → 检查新版启动 → 重启。

## 跨电脑接续方法

1. 两台电脑使用同一源码仓库的独立检出。先看 `git status`，保留未提交工作，再获取远端最新代码和交接文档；工作区干净时可用 `git pull --ff-only`。
2. 新聊天可以直接说：“这是焰轮哪吒源码仓库，请阅读 `AGENTS.md` 和 `docs/PROJECT_CONTEXT.md`，检查当前分支、未提交改动和近期提交，再接续本次任务。”
3. 需要同时开发时，用独立功能分支，合并前核对差异。顺序接续时，以已推送的源码和交接记录为共同依据。
4. 一轮结束后同步代码和本文件，记录实际验证和未完成事项。未推送的提交、未提交的代码、只留在某台电脑聊天里的决定，另一台电脑无法通过 Git 获取。
5. 文档改动本身不需要提升桌宠版本，也不需要发布新的程序包；只有需要向桌宠使用者分发程序改动时才走发布流程。

开发和发布命令见 [DEVELOPMENT.md](DEVELOPMENT.md) 与 [RELEASE.md](RELEASE.md)。其中公司电脑的 C 盘绝对路径是历史环境说明；新环境按用户要求选择非系统盘源码目录，不照搬旧路径。

# 后续功能路线

2026-10-01 用户调整优先级：先接入可扩展的办公室休闲小游戏。`codex/mini-games` 的 0.5.0 开发版已有扫雷、贪吃蛇和 2048，以及可调小窗、暂停 / 收起和文件夹扩展接口；详见 [小游戏使用与扩展](MINI_GAMES.md)。公司电脑还有未同步的动作工作，本轮保留现有动作与成长规则。下表保留较早的养成路线建议，后续顺序由试玩反馈再确定。

先让哪吒更像一个会回应、会休息的小伙伴，再增加每天的小目标和能花金币买到的外观。等级继续承担“解锁新玩法”的作用，先不增加复杂的装备数值。

## 已有基础

- 离线运行的 Windows 桌宠：拖动、透明区域穿透、部位点击、托盘与养成面板。
- 桂花糖、莲蓉包、仙桃各有一套 Q 版吃东西动画。
- 打工赚金币、买零食、喂食、累计经验、等级解锁与一次性成长礼。
- 公开 GitLab 源码仓库与发布包；使用者检查更新无需令牌，更新保留 `data` 存档。

## 按这个顺序继续

| 阶段 | 做什么 | 为什么先做 | 完成时能看见什么 |
| --- | --- | --- | --- |
| 0.4：互动与休息 | 摸头、挠身体、睡觉专属动作；神环和风火轮反馈；避免动作互相打断；休息恢复体力 | 现有养成规则已能玩，先补人物的回应和“打工后休息”的闭环 | 点击不同部位有明显区别；完整吃完再回应；能让哪吒睡一会儿并恢复体力 |
| 下一步：每日小目标 | 几个简单每日任务，如摸摸、喂一次、完成一份工作；完成提示与一次性奖励 | 给每天打开桌宠一个小目标，也能引导新用户理解已有玩法 | 能看到任务进度；领取后不会重复发奖；换日自动刷新 |
| 接着：金币的更多用途 | 商店增加小饰品、红绫配色或神环样式；背包中装备与卸下 | 现在金币主要买零食，外观能让打工与成长有更直观的回报 | 金币购买的物品可反复使用，关程序后外观仍保留 |
| 成长扩展 | 新等级解锁动作、外观与工作；增加图鉴或成就 | 新等级需要对应内容，先把奖励做出来，再延长等级路线 | 升级时明确知道解锁了什么，面板能预览下一级收益 |
| 根据试用补齐 | 开机启动开关、安装与卸载、多显示器和缩放适配、位置恢复 | 这些要围绕实际使用问题安排，避免在玩法尚未定型时过早做复杂安装器 | 不同电脑可稳定安装、更新、退出与继续存档 |

表中的“下一步”和后续阶段是建议顺序，还没有全部实现。每一阶段先做一个可玩的版本，实际试用后再决定是否继续扩充。

## 等级应当怎么设计

经验像积分，等级像会员档位。用户需要感受到“我升级后多了一个可以玩的东西”，所以优先让等级解锁新动作、外观、零食和工作。

当前 Lv.1～Lv.5 的门槛和收益先保留。每天互动、喂食的经验上限也先保留：这样可以照顾哪吒，又不会靠不停点击很快跳过全部内容。工作收益只给小幅加成；如果收益无限上涨，金币很快就失去购买目标。

新增等级前，先列一张“等级 → 解锁内容”的表。没有对应内容的等级暂不增加，不只为了让数字继续变大。

## 动作与养成数据分开

可以把动作理解成表演，把金币、体力和背包理解成账本。表演播放慢一点或临时卡顿，不应该让账本多扣一份零食或多领一次报酬。

每次操作的链路是：

1. **输入**：玩家点击身体部位、喂食按钮或休息按钮。
2. **检查**：当前是否正在打工、休息或播放需要完整看完的动作；背包和属性是否满足条件。
3. **结算**：规则层改变体力、背包或工作/休息状态。
4. **保存**：先完整写临时存档，再替换正式存档，保留上一份备份；失败时把本次内存变化退回。
5. **表现**：成功才播放对应动作、特效与反馈文字。

步骤 4 是“原子保存”：像换一本账本，写好新账本才拿它替换旧账本，避免写一半就断电留下半份数据。

动作优先级是“谁先表演”的规则。吃东西时先完整展示这次吃法，休息时保持睡觉动作，轻点或购物提示不能随意换掉它们；动作结束后再恢复合适的待机、打工或休息状态。规则层仍需要单独拒绝不允许的操作，不能只把按钮变灰。

## 休息为什么保存截止时间

休息与打工都适合保存“什么时候开始、什么时候结束、当时确定的恢复/奖励”。这份记录叫快照，相当于已经开出的订单：以后修改配置，也不应该把正在进行的订单改价。

开始休息后保存这份记录；程序关闭再打开时，睡眠状态仍保留，叫醒时再按本机当前时间与截止时间结算，避免只依赖窗口里的倒计时。结算完成后清除这条记录并保存，重复叫醒就不会重复恢复体力。这是个人离线桌宠，本机时钟变化仍会影响计时。

## 每次发布需要验收的边界

- 新版读到旧存档后，金币、背包、累计经验和已接工作都保留。
- 快速重复点击不会重复扣物品、领奖或恢复体力。
- 关闭再打开后，工作和休息仍按保存的时间与快照结算。
- 动作素材覆盖预期部位；吃东西能完整播放；特效透明区域仍能穿透鼠标。
- 发布包不含真实存档与发布凭证；更新成功后保留 `data`。
- 本机测试与另一台电脑的实际试用分别记录，不把本机通过当成全部电脑都通过。

后续主要投入会在新动作的画面一致性、动效制作和实际试玩。当前离线结构不需要新增服务器；每套新食物动画仍需要制作并检查一组完整动作帧。
